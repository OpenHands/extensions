Declare Events at the interface boundary

Canvas renders an Events source-management view, but the automation package must first declare its route, navigation identity, copy, and webhook endpoint. This PR changes the published manifest and its validation/type contract; it does not implement a second backend.

★ The change is additive for the automations interface, but the consumer cannot use it until a new extensions package is published and Canvas updates its exact pin. Manifest source: lines 3–20.

04 · Publishing and backend policy remain separate

⚠ A pinned Canvas installation will not expose Events with the old manifest. The automation backend already provides /v1/webhooks; its read permission currently checks view_automations, broader than an owner/admin-only Events-page policy. That backend authorization decision belongs in OpenHands/automation, not in this manifest.

Tested the manifest and schema on the rebased head with python -m pytest -q tests/test_interface_manifest.py (20 passing tests). Do not mistake a registration listing for successful event delivery; the observed local capabilities only advertise cron triggers.
