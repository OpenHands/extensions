## Findings outside this PR

1. **Blocker in OpenHands #17656 (inherited by #17660):** `createAppBackendViewClient` calls `createAppBackendSession(name, { signal })`, but the merged SDK client signature is `createAppBackendSession(name, signal?: AbortSignal)`; `AbortSignal.any([{signal}, timeout])` throws before any request and the helper shows "This app view is not available yet". It also pins `@openhands/typescript-client` 1.49.6, which has no `createAppBackendSession`. Unit tests mock the client. Local shim used here: `scripts/canvas-local-shim.diff` (pass `signal` directly).
2. **Cross-site ingress breaks OpenVSCode in current Chromium:** with Canvas and ingress on different sites (e.g. `localhost` vs `127.0.0.1`), Chromium 153's default third-party storage blocking denies `localStorage` in the iframe and the workbench never boots (`scripts/storage-probe.mjs` reproduces with a plain page). Deployments should keep the ingress same-site with Canvas (separate origin/subdomain).
3. **Upstream OpenVSCode webviews:** webviews load from `https://{{uuid}}.vscode-cdn.net` (upstream `product.json`); Chromium denies their service worker as third-party ("The user denied permission to use Service Worker"), so webview features (e.g. Markdown preview, walkthrough media) show "Error loading webview". Editor, Explorer, and save are unaffected. Not changed here: moving webviews same-origin would weaken webview isolation.

Not covered: arm64 runtime (amd64 runner), Cloud/remote workspaces, SPA-navigation session revoke (full page navigations were used).
